# 1. OBJETIVO DEL PROYECTO

Estamos construyendo un sistema web profesional para una nueva competición de **Rainbow Six Siege Drone Racing**, organizada para un evento de Ubisoft.

El sistema debe servir para:

* administrar la competición;
* introducir resultados manualmente;
* calcular automáticamente puntuaciones;
* mantener clasificación;
* actualizar todo en tiempo real;
* mostrar una Public Web profesional;
* generar overlays para broadcast/OBS;
* posteriormente generar estadísticas y exports.

**No existe API ni integración con el juego.**

Todos los resultados competitivos se introducen manualmente desde Admin.

Hay **2 operadores humanos**, ambos con permisos ADMIN.

---

# 2. CONCEPTO DE LA COMPETICIÓN

Actualmente hay 5 equipos/comunidades.

Seed actual:

* Caramelo
* Vetel
* Miwell
* SoraMusic
* Barra

Estos nombres son **seed data** y pueden cambiar cuando se configuren los nombres reales antes del evento.

* 1 Player 2

El Creator es el protagonista principal y participa en las 4 partidas.

---

# 3. FORMATO COMPETITIVO

## Partidas

Hay:

* 4 partidas principales.
* Cada partida tiene 3 mapas.
* Total: 12 mapas.

Cada mapa tiene 10 participantes:

* 5 creators.
* 5 jugadores de comunidad correspondientes a la rotación.

### Match 1

Cada equipo:

* Creator
* Player 1

### Match 2

Cada equipo:

* Creator
* Player 1

### Match 3

Cada equipo:

* Creator
* Player 2

### Match 4

Cada equipo:

* Creator
* Player 2

Por tanto:

```text
Creator → Match 1, 2, 3, 4
Player 1 → Match 1, 2
Player 2 → Match 3, 4
```

Los puntos de los participantes se acumulan para su equipo.

La clasificación principal es **por equipo**.

La clasificación individual es secundaria.

---

# 4. SISTEMA DE PUNTUACIÓN

Cada mapa tiene 10 participantes.

Puntuación:

| Posición | Puntos |
| -------- | -----: |
| 1º       |     25 |
| 2º       |     18 |
| 3º       |     15 |
| 4º       |     12 |
| 5º       |     10 |
| 6º       |      8 |
| 7º       |      6 |
| 8º       |      4 |
| 9º       |      2 |
| 10º      |      1 |
| DNF      |      0 |

Reglas:

* No hay empates dentro de un mapa.
* Puede haber múltiples DNF.
* Todo participante debe aparecer en los resultados.
* DNF tiene 0 puntos.
* El admin introduce la posición.
* El backend calcula los puntos.
* El frontend **NO calcula scoring competitivo**.

---

# 5. MATCH / MAP STATE MACHINE

Match:

```text
UPCOMING → LIVE → COMPLETED
```

Map:

```text
PENDING → ACTIVE → COMPLETED
```

Flujo:

```text
Admin START MATCH
        ↓
Match LIVE
        ↓
Map 1 ACTIVE
        ↓
Confirm Map 1
        ↓
Map 1 COMPLETED
Map 2 ACTIVE
        ↓
Confirm Map 2
        ↓
Map 2 COMPLETED
Map 3 ACTIVE
        ↓
Confirm Map 3
        ↓
Map 3 COMPLETED
Match COMPLETED
```

El inicio de cada match es manual.

La progresión de mapas dentro del match es automática.

El siguiente match espera a que el Admin lo inicie manualmente.

---

# 6. CORRECCIONES

Los resultados de mapas completados pueden corregirse.

Al corregir:

```text
Resultado corregido
      ↓
Scoring
      ↓
Player score
      ↓
Team score
      ↓
Ranking
      ↓
Historical snapshots
      ↓
Statistics futuras
      ↓
Realtime
```

Las correcciones deben recalcular todos los valores derivados.

No se deben guardar puntuaciones manuales independientes que puedan quedar desincronizadas.

---

# 7. TIEBREAK

El tiebreak solo puede ser necesario en la clasificación final.

Si hay empate final:

* el sistema muestra el empate;
* no existe fórmula automática de tiebreak actualmente.

El tiebreak es una fase independiente:

* 3 mapas;
* solo creators;
* mismo sistema de puntuación.

Si hay más de dos equipos empatados, el comportamiento concreto queda pendiente de definir.

**No inventar una regla.**

Room:

```text

```

```text
competition.updated
match.started
match.completed
map.started
map.completed
result.updated
ranking.updated
```

Flujo:

```text
Admin action
   ↓
Backend
   ↓
DB
   ↓
Scoring / Ranking
   ↓
Commit
   ↓
Socket.IO emit
   ↓
Public / Broadcast
```

Los eventos se emiten después del commit exitoso.

Socket.IO no es la fuente única de verdad.

Después de reconectar:

```text
Socket reconnect
      ↓
REST refetch
      ↓
local state actualizado
```
